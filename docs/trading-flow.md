# 每日交易流程

本文档详细描述系统在一个完整交易日中的运行流程，从启动到收盘。

## 一、流程总览

```
 启动          盘前分析      集合竞价        连续交易              尾盘           收盘
 ─────┬──────┬──────────┬──────────────┬────────────────────────┬────────────┬─────
      │      │          │              │                        │            │
  初始化   LLM预测    盘前卖出     Tick处理/买卖决策          清仓         复盘
  股票池   板块优先级   策略执行     板块/情绪监控              14:50       保存数据
  基因计算             订阅行情     止盈止损管理                           邮件报告
  共享数据                                                               绩效分析
```

## 二、详细阶段说明

### 阶段 1：系统初始化 (启动 → ~9:15)

**入口**: `main.py` → `main()`

#### 1.1 日志与连接

```python
init_logger(name='打板策略', log_dir='log')   # 初始化 loguru 日志
xtdata_connect(ip, port)                       # 连接 XTQuant 数据服务
```

- 日志按级别分文件存储：DEBUG / INFO / WARNING / ERROR / CRITICAL
- XTData 数据服务需提前在 QMT 客户端启动

#### 1.2 股票池初始化

**模块**: `core/stock_pool.py` → `init_stock_pool()`

```
全部 A 股
  ├── 排除 科创板 (688-) → 20% 涨跌幅，风险特征不同
  ├── 排除 北交所 (.BJ)  → 流动性不足
  ├── 排除 停牌股         → InstrumentStatus > 0
  ├── 排除 ST/*ST 股      → 名称含 'st'
  ├── 排除 新股 (N/C 股)  → 上市 < 5 天（加入新股列表）
  ├── 排除 次新股          → 上市 < 100 天
  ├── 排除 低价股          → 昨收 < 2 元
  │
  ▼ 每只股票采集信息
  ├── 涨停价 / 跌停价
  ├── 流通股本（优先 akshare，备用 xtdata）
  ├── 股票名称 / 昨收价
  ├── 60 日均线（60 天收盘价均值）
  └── 5 日平均成交量 / 成交额
```

**输出**: `(stock_pool, stock_info_dict, new_stock_list)`

#### 1.3 涨停基因计算

**模块**: `core/gene_calculator.py` → `get_strong_stocks()`

分两步进行：

**第一步：计算涨停基因指标** (`calculate_stock_gene()`)

对每只股票的过去 250 个交易日数据，计算：

| 指标 | 含义 |
|------|------|
| 封板成功率 | 涨停且成功收盘封住的比例 |
| 首板封板率 | 第一次涨停就封住的比例 |
| 连板率 | 连续涨停的比例 |
| 涨停次日开盘/收盘溢价 | 涨停后第二天的溢价幅度 |
| 近 5/10/20 日涨停次数 | 最近活跃度 |
| 近 20 日平均振幅 | 波动率（用于仓位管理） |

**第二步：过滤与评分** (`get_strong_stocks()`)

8 道过滤后，进行加权评分：

| 因子 | 权重 | 含义 |
|------|------|------|
| 涨停次日收盘溢价超5%比例 | 25% | 封板后次日有高溢价的概率 |
| 首板次日收盘红盘率 | 25% | 首板后次日收红的概率 |
| 首板封板率 | 25% | 首板封板成功概率 |
| 涨停次数 | 10% | 历史涨停活跃度 |
| 首板涨停/炸板次日开盘平均溢价 | 15% | 开盘溢价空间 |

**输出**: 前 1000 只强势股票列表 → 缓存到 `output/强势股票/`

#### 1.4 板块映射加载

**模块**: `data/sector_mapping.py`

加载同花顺板块分类数据：
- 概念板块映射：`output/concept_sectors/THS/` JSON 文件
- 行业板块映射：`output/industry_sectors/THS/` JSON 文件
- 昨日涨停/首板涨停股票列表

#### 1.5 共享数据初始化

**模块**: `data/shared_data.py` → `init_shared_data()`

创建跨进程共享的数据结构体系：

```python
shared_data = {

    # --- 实时状态 ---

### 阶段 3：开盘与盘前卖出 (9:25 ~ 9:30)

**模块**: `core/pre_market_sell.py` → `execute_pre_market_sell_strategy()`

交易进程启动后，首先处理昨日持仓的盘前挂单：

```
昨日持仓股票
    │
    ├── 昨日涨停封住的股票 → 使用配置的盘前卖出策略
    │   ├── TIERED_SELL:         1/4 在昨收+5%挂卖，1/4 在涨停价挂卖，1/2 持有
    │   ├── FIXED_PREMIUM_SELL:  全部在昨收+2%挂卖（默认策略）
    │   ├── LIMIT_UP_SELL:       全部在涨停价挂卖
    │   └── NO_PRE_MARKET_SELL:  不做盘前挂单
    │
    └── 其他持仓股票 → 止损检查
        └── 昨收 < 成本 × (1 - 5%) → 在跌停价挂卖（止损）
```

同时为每只持仓股计算**追踪止损价格数组**（10 档），用于盘中动态止损。

---

### 阶段 4：连续交易 (9:30 ~ 14:50)

这是系统的核心运行阶段，多个进程并行工作。

#### 4.1 行情订阅

**模块**: `engine/tick_processor.py` → `create_whole_quote_task()`

- 调用 `xtdata.subscribe_whole_quote()` 订阅全市场 Tick 数据
- 每个 Tick 回调通过 `on_data()` 函数推入 `tick_queue`
- 心跳监控：每 5 秒检查回调是否正常，超时 30 秒发送邮件告警

#### 4.2 Tick 处理循环

**模块**: `engine/tick_processor.py` → `process_tick_data()`

8 个工作进程从队列消费 Tick 数据，对每只股票执行：

```
收到 Tick 数据
    │
    ├── 1. 判断价格状态
    │   ├── is_limit_up:      当前价 = 涨停价
    │   ├── is_near_limit_up: 当前价 ≥ 涨停价 × 0.98
    │   └── is_down_limit:    当前价 = 跌停价
    │
    ├── 2. 更新股票状态信号
    │   ├── 首次涨停 → 加入涨停池，记录时间
    │   ├── 炸板 → 标记为 LIMIT_UP_BROKEN，加入炸板池
    │   ├── 回封 → 标记为 LIMIT_UP_REBOUND
    │   └── 更新封单金额、拉板所需资金
    │
    ├── 3. 更新最高价 → 重新计算追踪止损
    │
    ├── 4. 检查买入信号
    │   └── should_buy() → 满足则推入 order_queue
    │
    ├── 5. 检查撤单信号
    │   └── should_cancel() → 满足则推入 order_queue
    │
    └── 6. 检查卖出信号
        └── should_sell() → 满足则推入 order_queue
```

                            │

  │         前置检查（任一不满足即拒绝）                 │
  │                                                    │
  │  □ 当前时间 < 14:50                                │

  │  □ 市场情绪 ≥ 2.5                                  │

  │ □ 撤单次数 < 上限       │  │ □ 情绪 ≥ 4         │
  │ □ 封单额 ≥ 2000万       │  │ □ 拉板资金 < 300万  │
  │ □ 封单额 ≥ 动态阈值*    │  │ □ 价格未回落        │
  │ □ 板块数 ≥ 动态要求**    │  │ □ 板块数/领涨数    │
  │ □ 领涨数 ≥ 动态要求**    │  │   ≥ 动态要求       │

              │                           │
              ▼                           ▼
         提交限价买入                 提交限价买入

```

*动态阈值：通过 `interpolate_seal_threshold(情绪评分)` 连续插值计算

**情绪→封单阈值对应关系**:

| 情绪评分 | 封单阈值(万元) | 市场状态 |
|---------|---------------|---------|
| 10.0 | 2,000 | 极强 |
| 8.0 | 3,000 | 强势 |
| 7.0 | 5,000 | 偏强 |
| 5.5 | 8,000 | 中性 |
| 4.0 | 10,000 | 偏弱 |
| 2.5 | 15,000 | 弱势 |
| 1.0 | 20,000 | 极弱 |

中间值通过线性插值计算，无阶梯跳变。

**LLM 板块折扣**：如果股票所属板块在 LLM 预测的优先板块中，封单阈值额外打 7 折。

#### 4.4 撤单决策

**模块**: `core/decisions.py` → `should_cancel()`

**买单撤单条件**（满足任一即撤单）：
- 封单金额 < 2000 万且不在涨停
- 封单变化率 < -20%（大幅缩量）且封单低于情绪对应阈值
- 换手率 ≥ 25%（加入黑名单）
- 个股资金流入信号消失
- 时间超过 14:55 仍未成交

**卖单撤单条件**（针对固定价格挂单）：
- 触发止损：当前价 < 成本 × (1 - 5%) → 撤销固定价卖单，改市价卖出
- 时间超过 14:50 仍未成交 → 撤销固定价卖单，改市价卖出

#### 4.5 卖出决策

**模块**: `core/decisions.py` → `should_sell()`

```
持仓股票卖出触发
    │
    ├── 时间触发：14:50 后 → 市价全部清仓
    │
    ├── 跌停触发：当前价 = 跌停价 → 跌停价全部挂卖
    │
    ├── 接近涨停触发：接近涨停价 → 市价全部清仓（锁定利润）
    │
    ├── 日内分档止盈 (v3.0)
    │   ├── 盈利 ≥ 5% → 卖出 25%（首次触发）
    │   ├── 盈利 ≥ 8% → 再卖 25%
    │   └── 盈利 ≥ 10% → 再卖 25%
    │
    └── 动态追踪止损 (v3.0)
        └── 遍历 10 档止损价格数组
            └── 当前价 < 止损价[i] → 卖出到目标仓位[i]
```

#### 4.6 追踪止损详解

**模块**: `core/trailing_stop.py` → `calculate_trailing_stop_prices()`

追踪止损是 v3.0 的核心创新，替代了传统的固定成本止损：

**核心思路**：以最高价为锚点，根据盈利水平动态调整回撤容忍度。

**Step 1 - 确定止损率**：

| 盈利水平 | 追踪止损率 | 策略含义 |
|---------|-----------|---------|
| ≥ 10% | 2.5% | 高盈利要紧紧保护，最高价回撤 2.5% 就启动止损 |
| 5% ~ 10% | 3.0% | 中等盈利，适度保护 |
| 2% ~ 5% | 4.0% | 低盈利，给予一定波动空间 |
| < 2% | 5.0% | 刚买入不久，容忍正常波动 |

止损价 = max(最高价 × (1 - 追踪率), 成本 × 0.95, 跌停价)

**Step 2 - 10 档价格分布**：

根据"距涨停距离比"选择不同的阶梯分布策略：

| 距离比 | 前端步长 | 后端步长 | 策略 |
|-------|---------|---------|------|
| ≤ 20% (接近涨停) | 窄 (2-3%) | 宽 | 激进保护高位利润 |
| 20-40% | 适中 | 适中 | 平衡 |
| 40-60% | 平均 | 平均 | 均匀分布 |
| > 60% (远离涨停) | 宽 (8-12%) | 窄 | 容忍大波动 |

**Step 3 - 动态减仓比例**：

| 盈利水平 | 10 档仓位保留比 (%) | 策略名称 |
|---------|------|---------|
| ≥ 5% | 100→85→70→55→40→25→15→8→3→0 | 激进保护 |
| 3-5% | 100→90→80→65→50→35→20→10→3→0 | 积极保护 |
| 2-3% | 100→100→85→70→55→40→25→12→5→0 | 适度保护 |
| 1-2% | 100→100→100→80→65→45→30→15→5→0 | 保守保护 |
| 0-1% | 100→100→100→100→75→55→35→20→8→0 | 宽容策略 |
| < 0% | 100→100→100→100→100→75→55→35→15→0 | 止损策略 |

#### 4.7 监控任务

**板块监控** (`monitor/sector_monitor.py`):
- 每 10 秒拉取东方财富板块涨幅数据
- 过滤涨幅 ≥ 1.5% 的板块
- 更新概念/行业板块效应到共享数据
- 每 60 秒检查观察名单自动释放（30 分钟超时）

**情绪监控** (`monitor/sentiment_task.py` + `indicators.py`):
- 每 3 秒计算涨停数、炸板数、炸板率
- 每 3 秒拉取同花顺涨停/首板整体表现
- 每 5 秒计算大盘指数涨跌
- 综合评分模型（基准 5 分 ± 各因子加减分）→ 最终 1-10 分
- 每 5 分钟发送 HTML 邮件报表

---

### 阶段 5：尾盘清仓 (14:50 ~ 15:00)

- 14:50 (`CLEAR_TIME`)：所有持仓自动市价清仓
- 14:55 (`BUY_ORDER_CANCEL_DEADLINE`)：所有未成交买单自动撤单
- 15:01 (`STOP_TIME`)：系统停止

---

### 阶段 6：收盘处理 (15:00+)

#### 6.1 数据保存

**模块**: `infra/trade_log.py` → `save_daily_limit_up_list()`

- 保存今日涨停列表 → `output/涨停列表/涨停_{TODAY}.txt`
- 保存今日首次涨停列表 → `output/涨停列表/首次涨停_{TODAY}.txt`
- 保存今日炸板列表 → `output/涨停列表/炸板_{TODAY}.txt`
- 发送邮件汇总

#### 6.2 盘后复盘

**模块**: `analysis/post_market_review.py`

以子进程方式执行盘后分析：

- 加载涨停基因数据 + 共享数据备份 + 交易日志
- 解析 DEBUG 日志中的过滤记录和决策记录
- 计算每个过滤条件的**精确率 (Precision)**、**召回率 (Recall)**、**F1-Score**
- 分析错过的机会（被拒绝但实际涨停的股票）
- 生成 HTML + JSON 报告

#### 6.3 每日绩效报告

**模块**: `analysis/review_daily.py`

- 匹配买入/卖出配对
- 计算：胜率、平均盈亏、盈亏比、总收益、最大单笔盈亏
- 生成 Markdown 格式报告
