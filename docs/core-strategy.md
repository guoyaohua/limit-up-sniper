# 核心策略模块

本文档详细说明 `core/` 目录下的核心策略逻辑。

## 一、模块总览

| 文件 | 职责 | 核心函数 |
|------|------|----------|
| `stock_pool.py` | 交易股票池初始化 | `init_stock_pool()` |
| `gene_calculator.py` | 涨停基因计算与强势股筛选 | `calculate_stock_gene()`, `get_strong_stocks()` |
| `decisions.py` | 实时买入/撤单/卖出决策 | `should_buy()`, `should_cancel()`, `should_sell()` |
| `trailing_stop.py` | 动态追踪止损计算 | `calculate_trailing_stop_prices()` |
| `pre_market_sell.py` | 盘前卖出策略执行 | `execute_pre_market_sell_strategy()` |
| `interpolation.py` | 连续插值函数 | `interpolate_seal_threshold()`, `interpolate_sector_requirements()` |

## 二、股票池初始化 (`stock_pool.py`)

### 2.1 `add_stock_code_suffix(code: str) -> str`

将纯数字股票代码转换为带交易所后缀的代码：

| 前缀 | 交易所 | 后缀 | 示例 |
|------|--------|------|------|
| 6, 900 | 上海 | .SH | 600000 → 600000.SH |
| 0, 3, 200 | 深圳 | .SZ | 000001 → 000001.SZ |
| 8, 920 | 北京 | .BJ | 830001 → 830001.BJ |

### 2.2 `init_stock_pool(end_date) -> tuple[list, dict, list]`

**完整股票池初始化流程**：

```
输入: end_date (上一个交易日)
输出: (stock_pool, stock_info_dict, new_stock_list)
```

**处理流程**：

1. **获取流通股本数据**
   - 数据源：akshare `stock_hold_change_cninfo()` + xtdata
   - 构建 `{股票代码: 流通股数}` 映射

2. **下载板块数据**
   - 调用 `xtdata.download_sector_data()`

3. **获取全部 A 股列表**
   - 调用 `xtdata.get_stock_list_in_sector('沪深A股')`
   - 排除科创板 (688-) 和北交所 (.BJ)

4. **逐股验证与过滤**

   对每只股票调用 `xtdata.get_instrument_detail()` 检查：

   | 检查项 | 规则 | 排除原因 |
   |--------|------|---------|
   | 停牌状态 | InstrumentStatus > 0 | 无法交易 |
   | ST 标记 | 名称含 'st' (不区分大小写) | 涨跌幅 5%，策略不适用 |
   | 未上市 | OpenDate 无效或 ≥ 今天 | 未开始交易 |
   | 新股 | 名称以 'N' 或 'C' 开头 | 上市不足 5 天，波动剧烈 |
   | 次新股 | 上市 < 100 天 | 历史数据不足 |
   | 低价股 | 昨收 < 2 元 | 流动性差，易被操纵 |

5. **采集每只股票的信息**

   ```python
   stock_info_dict[code] = {
       '涨停价': limit_up_price,     # 昨收 × 1.10 (主板) / 1.20 (创业板)
       '跌停价': limit_down_price,    # 昨收 × 0.90 / 0.80
       '流通股本': float_volume,      # 流通股数量
       '股票名称': name,
       '昨日收盘价': pre_close,
       '60日均线': ma60,              # 后续填充
       '5日平均成交量': avg_vol_5d,   # 后续填充
       '5日平均成交额': avg_amount_5d # 后续填充
   }
   ```

6. **计算历史指标**
   - 60 日均线：60 天收盘价移动平均
   - 5 日均量/均额：近 5 日成交量/成交额平均

## 三、涨停基因计算 (`gene_calculator.py`)

### 3.1 `calculate_stock_gene(data, N=250) -> pd.DataFrame`

对单只股票的历史 K 线数据（最近 N 个交易日），计算一套"涨停基因"指标。

**输入参数**：
- `data`: DataFrame，必须包含 `open`, `close`, `high`, `low`, `volume` 列
- `N`: 统计窗口大小，默认 250 个交易日（约 1 年）

**计算的每日基础标记**：

| 标记 | 计算方式 | 含义 |
|------|---------|------|
| 涨停 | close ≥ 涨停价 - 0.0001 | 当日收盘涨停 |
| 炸板 | high ≥ 涨停价 - 0.0001 且 close < 涨停价 | 盘中触及涨停但未封住 |
| 连板次数 | 连续涨停天数累计 | 2 连板、3 连板等 |
| 封板成功 | 涨停 = 1.0, 炸板 = 0.0 | 封板成功/失败 |
| 首板封板 | 连板次数=1 且封板成功 | 第一次涨停就封住 |

**计算的滚动窗口指标** (N 日窗口)：

| 指标 | 计算方式 | 用途 |
|------|---------|------|
| 封板成功率 | sum(封板成功) / count(涨停+炸板) | 评估封板能力 |
| 首板封板率 | sum(首板封板) / count(首板事件) | 首次涨停封板概率 |
| 连板率 | sum(连板) / count(涨停) | 连续涨停概率 |
| 涨停次数 | N 日内涨停总次数 | 活跃度 |
| 近 5/10/20 日涨停次数 | 短周期涨停计数 | 近期活跃度 |
| 涨停次日开盘溢价 | mean(次日开盘价/涨停收盘价 - 1) | 次日开盘溢价空间 |
| 涨停次日收盘溢价 | mean(次日收盘价/涨停收盘价 - 1) | 次日收盘溢价空间 |
| 涨停次日收盘溢价超5%比例 | count(次日溢价>5%) / count(涨停) | 高溢价事件频率 |
| 首板次日收盘红盘率 | count(首板次日close>close) / count(首板) | 首板后次日收红概率 |
| 近 20 日平均振幅 | mean((high-low)/close) | 日内波动率 (U6 仓位管理) |

### 3.2 `get_strong_stocks(stock_pool, stock_info_dict, end_date) -> list`

**功能**：从股票池中筛选涨停基因最强的 1000 只股票。

**缓存机制**：结果缓存到 `output/强势股票/强势股票_{TODAY}.csv`，当日重复运行直接读取。

**八道过滤条件**：

| 序号 | 条件 | 阈值 | 原因 |
|------|------|------|------|
| 1 | 流通市值 | ≥ 10 亿元 | 排除小盘股，避免被操纵 |
| 2 | 涨停价 vs 60日均线 | 涨停价 ≥ MA60 | 确保趋势向上 |
| 3 | 5日平均成交额 | ≥ 1 亿元 | 确保充足流动性 |
| 4 | 昨日收盘价 | ≥ 5 元 | 排除低价股 |
| 5 | 近 5 日涨停情况 | 无涨停 | 排除连板股（策略只做首板） |
| 6 | 溢价质量 | 开盘或收盘平均溢价 ≥ 1% | 确保有正向溢价空间 |
| 7 | 历史涨停次数 | > 0 | 必须有涨停经验 |
| 8 | 首板封板率 | ≥ 70% | 封板能力强 |

**五因子加权评分**：

```
涨停基因得分 = 0.25 × rank(涨停次日收盘溢价超5%比例)
             + 0.25 × rank(首板次日收盘红盘率)
             + 0.25 × rank(首板封板率)
             + 0.10 × rank(涨停次数)
             + 0.15 × rank(首板涨停/炸板次日开盘平均溢价)
```

每个因子先做百分位排名 (0-100)，再加权求和。取 Top 1000。

## 四、买卖决策引擎 (`decisions.py`)

这是系统最核心的模块，包含三大决策函数。

### 4.1 `leading_stock_check(sector_info, stock_code) -> tuple[int, int]`

**功能**：检查股票是否为板块领涨股。

**参数**：
- `sector_info`: JSON 字符串，包含板块信息（板块代码、板块名、涨幅、领涨股等）
- `stock_code`: 股票代码

**返回**：`(total_sectors, leading_count)` — 涉及的板块总数和领涨的板块数

**逻辑**：
1. 解析 `sector_info` JSON 为 DataFrame
2. 去除股票代码后缀（.SH/.SZ）
3. 遍历每个板块，检查该股票是否在板块的领涨股列表中
4. 统计总板块数和领涨板块数

### 4.2 `should_buy()` — 买入决策

> 详细流程参见 [每日交易流程 → 4.3 买入决策](trading-flow.md)

**两种买入模式**：

#### 排板 (Ranking Board)

在涨停价挂限价买单排队等待成交。适用于已经封死涨停的股票。

**核心门槛**：
- 封单金额 ≥ 动态阈值（由市场情绪插值计算）
- 板块效应存在且板块数量/领涨数量达标

#### 扫板 (Sweeping Board)

在涨停价附近挂限价买单快速成交。适用于价格接近但未到涨停的股票。

**核心门槛**：
- 市场情绪 ≥ 4（中性偏强以上才允许扫板）
- 拉板所需资金 < 300 万元（主力已接近封板）
- 价格处于上升趋势（当前价 ≥ 前一价格）

### 4.3 `should_cancel()` — 撤单决策

**买单撤单的五个触发条件**：

| 条件 | 阈值 | 逻辑说明 |
|------|------|---------|
| 开板 | 股价不在涨停 | 涨停打开，封板失败 |
| 封单缩量 | 变化率 < -20% 且低于情绪阈值 | 主力撤单信号 |
| 高换手率 | ≥ 25% | 筹码过度换手，纯游资博弈 |
| 资金流出 | 个股资金流入信号消失 | 主力资金流出 |
| 超时未成交 | 14:55 后 | 避免夜间持仓风险 |

**卖单撤单的两个触发条件**：

| 条件 | 逻辑说明 |
|------|---------|
| 触发止损 | 当前价 < 成本 × 0.95 → 撤固定价卖单，换市价卖出 |
| 超时未成交 | 14:50 后 → 撤固定价卖单，换市价清仓 |

### 4.4 `should_sell()` — 卖出决策

**卖出优先级（从高到低）**：

1. **尾盘清仓** (14:50+)：市价卖出全部可用仓位
2. **跌停卖出**：以跌停价挂卖全部
3. **接近涨停卖出**：市价卖出全部（锁利）
4. **日内分档止盈** (v3.0)：按盈利档位逐步减仓
5. **追踪止损** (v3.0)：对照 10 档止损价格数组执行减仓

### 4.5 换手率分级处理 (U5)

| 换手率 | 处理 | 后续影响 |
|--------|------|---------|
| ≥ 25% | 加入黑名单 | 永久拒绝买入（当日） |
| 15% ~ 25% | 加入观察名单 | 仓位减半，30 分钟后自动释放 |
| 3% ~ 15% | 正常交易 | 无影响 |
| < 3% | 拒绝买入 | 流动性不足 |

## 五、动态追踪止损 (`trailing_stop.py`)

### 5.1 `calculate_trailing_stop_prices(highest_price, limit_down_price, stock_code, shared_data)`

> 详细算法参见 [每日交易流程 → 4.6 追踪止损详解](trading-flow.md)

**核心创新**：
- **纯追踪止损**：以盘中最高价为锚点（非固定成本价），价格上涨时止损价自动上移
- **动态收窄**：盈利越高，回撤容忍度越小
- **10 档阶梯**：从最高价到止损价之间分 10 档价位，每档对应不同的目标仓位
- **非线性分布**：根据距涨停距离调整各档步长分布

**输出**：更新 `shared_data['股票状态信号'][stock_code]` 中的两个数组：
- `止盈止损价格列表`: Array('d', 10 elements) — 10 个价格档位
- `目标剩余仓位`: Array('i', 10 elements) — 每档对应的目标持仓量

## 六、盘前卖出策略 (`pre_market_sell.py`)

### 6.1 `execute_pre_market_sell_strategy(xt_trader, acc, stock_code, ...)`

**四种策略**：

| 策略 | 适用场景 | 挂单方式 |
|------|---------|---------|
| `TIERED_SELL` | 昨日涨停股 | 1/4 在昨收+5%，1/4 在涨停价，保留 1/2 |
| `FIXED_PREMIUM_SELL` (默认) | 昨日涨停股 | 全部在昨收+2% 或涨停价（取较高者） |
| `LIMIT_UP_SELL` | 昨日涨停股 | 全部在涨停价 |
| `NO_PRE_MARKET_SELL` | - | 不挂盘前卖单 |

**非涨停持仓**：仅执行止损检查（昨收 < 成本 × 0.95 → 跌停价挂卖）。

## 七、连续插值 (`interpolation.py`)

### 7.1 `interpolate_seal_threshold(sentiment_score) -> float`

将市场情绪评分 (1-10) 连续映射到封单金额阈值 (元)。

**锚点定义**：

```python
anchors = [
    (10.0, 2000万),   # 极强市场，低门槛即可买入
    (8.0,  3000万),
    (7.0,  5000万),
    (5.5,  8000万),
    (4.0,  10000万),
    (2.5,  15000万),  # 弱市，要求极高封单
    (1.0,  20000万),
]
```

在锚点之间进行线性插值，消除传统 if-else 阶梯函数的跳变问题。

### 7.2 `interpolate_sector_requirements(sentiment_score) -> tuple[int, int]`

将情绪评分映射到 (所需板块数, 所需领涨数)。

逻辑类似：情绪越高，板块数和领涨数要求越低；情绪越低，要求越严格。
