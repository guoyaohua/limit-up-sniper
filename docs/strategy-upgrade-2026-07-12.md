# 策略升级说明与验证计划（2026-07-12）

> 本文记录本轮已经落地的策略与研究基础设施升级，以及后续上线验收口径。
> 它不是收益承诺：现有历史数据不足以证明封板率、胜率或收益率已经提高。

## 结论摘要

本轮升级优先解决了会让研究结论失真的问题，再扩大首板发现范围：

1. 修复未来数据泄漏、统计分母、量能时段、扫板资金方向、陈旧数据和
   同股 Tick 乱序等确定性问题。
2. 将盘前发现从少量热榜扩展到 1 小时/24 小时热股、概念/行业热度和
   涨停基因池，并把候选分为核心层与观察层。
3. 昨日涨停股票只用于题材延续/退潮研判，不再进入今日首板候选；模型输出的
   股票代码和证据会由本地数据二次校验。
4. 新增持久化模拟/影子账户、可校验 Tick 归档、事件驱动回测和真实决策事件回放。
5. 排板撮合采用保守规则，只有新增成交量穿透“前方队列 + 本单”且盘口仍封板
   才确认整单成交，避免把无法成交的涨停收益算入策略。

这些修改提高了数据、信号和成交统计的可信度，也建立了验证策略的闭环；是否真正
提高封板率和收益率，仍须用至少 20 个交易日的同源 A/B 数据确认。

## 一、策略与数据正确性修复

### 1. 消除研究偏差

- 涨停基因中的次日开盘/收盘标签只有在结果已经可观测后才进入滚动特征，避免
  用“明天”的数据参与今天选股。
- 次日溢价比例只使用已经结算的样本作分母，不再把尚未发生的明日结果记为失败。
- Tick 回测默认在信号后的下一笔该股票行情成交，避免信号生成与成交共用同一盘口。
- 打板封板率按每次入场所属交易日分别结算；信号、排板队列和收盘状态不跨日复用。

### 2. 修复信号与执行语义

- 扫板“拉板所需资金”改为统计涨停价以内待吃的委卖盘，不再误用买盘深度。
- 盘中量比按连续竞价已交易分钟折算预期全天成交量，并排除午休，减少对早盘
  快速放量股票的系统性压制。
- 板块和个股资金流缺少时间戳或超过有效期时停止买入；从备份恢复后先清空
  派生实时信号，等待监控重新填充。
- 股票代码按字符串读取并校验属于当前股票池，避免前导零丢失或陈旧缓存污染。
- Tick 按股票代码固定分片到 FIFO 队列，保证同一股票的前价、开板、回封和盘口
  趋势按原始顺序处理。
- 价格一次跨越多个止盈档时，会补齐全部尚未触发的档位。

### 3. 保留的风险保护

本轮没有为了扩大覆盖而删除以下保护：

- 市场情绪低于 2.5 时停止买入；
- 开板后深跌、开板时间过长等炸板风险过滤；
- 换手率 25% 以上黑名单、15%-25% 观察名单降仓；
- 单板块最多两只、最多六只持仓等集中度约束；
- 5%/8%/10% 分档止盈和追踪止损框架。

## 二、盘前首板发现与 Prompt 升级

盘前模块现在以“扩大召回但不绕过盘中风控”为边界。主要覆盖范围如下：

| 输入层 | 当前上限 | 作用 |
|---|---:|---|
| 1 小时热股 | 100 | 捕捉盘前新发酵和快速轮动 |
| 24 小时热股 | 100 | 确认持续热度 |
| 概念热度 | 50 | 识别题材共振 |
| 行业热度 | 50 | 识别行业级联动 |
| 涨停基因池 | 500 | 补足尚未进入热榜的低位首板候选 |
| 送入 Prompt 的合并证据 | 260 | 控制上下文长度并保留多源覆盖 |
| LLM 候选输出 | 30 | 核心层和观察层合计 |
| 核心候选 | 12 | 置信度不低于 0.78 且至少两类本地证据 |

新版 Prompt 同时要求研究延续主线、轮动支线和新发酵题材，明确区分：

- `core`：多源共振且风险可控；
- `watch`：单一来源、题材映射待确认或证据较弱，只保留观察资格。

LLM 不是信任边界。代码会使用本地输入重建 `evidence_sources`，拒绝输入证据中
不存在的代码和板块，也不会允许单一来源被模型重复描述成“多源”。昨日涨停代码在
热榜、基因池和输出校验链路中统一排除，只保留在题材研判区。

扩展候选在模拟模式可进入模拟强势池；实盘模式下不会修改主策略核心池，只进入独立
影子策略。无论来自哪一层，最终买入仍须通过盘中盘口、资金流、板块联动、市场情绪、
换手率、持仓和集中度检查。

## 三、模拟、影子与实时收益

系统现在支持三条明确隔离的执行路径：

| 模式 | 行情 | 策略状态 | 委托与收益 |
|---|---|---|---|
| 模拟 | 实时 XTQuant | 模拟主策略 | 只写纸面账户 |
| 实盘 + 影子 | 同一份实时 Tick | 主策略与影子策略独立 | 主策略发 QMT，影子只写纸面账户 |
| 离线回测 | Tick 归档 | 回测实例 | 内存纸面账户 |

`PaperBroker` 统一模拟和回测的成交口径，包含：

- SQLite 持久化、稳定 `signal_id` 幂等和崩溃恢复；
- A 股 100 股整数手、T+1 可卖限制；
- 五档盘口 VWAP、盘口参与率和限价约束；
- 双边佣金、最低佣金、卖出印花税、过户费和滑点；
- 实时持仓市值、已实现/未实现盈亏与净值曲线。

主策略和影子策略事件分别标记为 `primary` 与 `shadow`，防止后续回放混样。没有
来源标签的旧事件默认拒绝；只有研究者明确接受歧义时才允许兼容读取。

## 四、Tick 归档与防偏差回测

### 1. Tick 归档

[`capture_ticks.py`](../scripts/capture_ticks.py) 将每个行情回调保存为不可变的
gzip JSONL 分段，保留原始五档数组、事件时间、接收时间、回调批次、采集 session
和股票代码。每段都有 manifest 与 SHA-256。以下情况会 fail closed，不能静默进入
严谨回测：

- 空归档或缺失 manifest；
- 回调队列丢包；
- 后台写盘异常；
- 记录数、批次数、顺序、重复键或摘要校验失败。

### 2. 回测与事件回放

[`run_backtest.py`](../scripts/run_backtest.py) 支持自定义策略插件，也可直接回放
`events.jsonl` 中的真实主策略/影子策略决策。核心约束包括：

- 信号按日志时间对齐，只能在生成后生效；
- 扫板在下一笔该股票 Tick 撮合；
- 排板必须满足新增成交手数大于等于下单时前方队列手数与本单手数之和，并且
  确认时仍封板；
- 封单减少可能来自撤单，不计作成交；开板、撤单和跨日会使旧排板队列失效；
- 重复事件、来源混淆和不完整 Tick 数据默认拒绝。

回测输出同时提供收益、最大回撤、费用、胜率、盈亏比、净值曲线和打板专用指标。
胜率与收盘封板率都报告 Wilson 95% 置信区间；没有样本时返回 `null`，避免把
“没有交易”误读成 0% 胜率。完整操作见[Tick 回测与影子交易](backtesting.md)。

## 五、现有证据与结论边界

旧项目可迁移数据仅包含：

| 指标 | 数量 |
|---|---:|
| 交易日 | 12 |
| 当日涨停样本 | 1,000 |
| 炸板样本 | 316 |
| 策略通过 | 55 |
| 实际买入记录 | 25 |
| “后来涨停”错失标记 | 884 |

这些记录没有完整买卖配对和连续净值曲线。旧报告中的 `success_rate` 是捕获/封板
口径，不是扣除费用后的交易胜率；“后来涨停”也不等于当时盘口可成交或次日可盈利。
因此当前不能宣称：

- 封板率已经提高；
- 实际胜率或收益率已经提高；
- 最大回撤已经降低；
- 扩展候选优于原核心池。

已能确认的是：未来函数和多项确定性错误得到修复，候选召回与实盘执行实现隔离，
并且收益、成交和封板表现现在可以用统一口径持续测量。

## 六、核心池与扩展影子池 A/B 验收

### 1. 实验设计

- A 组：原核心强势池；B 组：核心池加盘前扩展候选。
- 两组使用相同 Tick、同一代码版本、同一参数快照和同一 `PaperBroker` 成本假设。
- 实盘主账户与影子纸面账户不直接比较成交价格；应把 `primary` 和 `shadow` 事件
  重新放入同一回放撮合器，保证执行假设一致。
- 至少覆盖 20 个交易日，并包含强势、分歧和弱势市场。若有效成交样本过少、
  Wilson 区间仍很宽，则继续观察，不以日历天数强行得出结论。
- 参数和筛选规则在验证窗口开始前冻结；窗口内发现的问题记录到下一版本，避免
  边看结果边调参造成过拟合。

### 2. 必报指标

| 维度 | 指标 |
|---|---|
| 覆盖 | 候选数、有效信号数、可成交信号数 |
| 成交真实性 | 成交数、未成交率、排板队列失效/撤单/跨日比例 |
| 封板质量 | 收盘封板率、炸板率、Wilson 95% 区间 |
| 后续表现 | 次日开盘/收盘收益、最大有利/不利波动 |
| 交易绩效 | 扣费净收益、胜率及区间、平均单笔收益、Profit Factor |
| 风险 | 最大回撤、单笔最大亏损、行业/题材集中度 |
| 稳健性 | 费用、滑点、盘口参与率敏感性及不同市场阶段分组 |

### 3. 晋级原则

扩展池只有在样本外窗口中同时满足以下条件，才可考虑小规模晋级到实盘核心池：

1. 数据完整性全部通过，且没有把不可成交排板当成盈利交易；
2. 扣费净收益、Profit Factor 和封板质量相对 A 组有改善或至少不退化；
3. 最大回撤和最大单笔亏损不突破预先登记的风险容忍度；
4. 改善不只来自一只股票、一个题材或单一强势阶段；
5. 在更高费用/滑点、更低盘口参与率的压力情景下结论不反转。

若条件不满足，B 组继续留在影子模式，不通过放宽实盘风控来追求表面交易频率。

## 七、七维一致性终审

| 检查维度 | 结论 |
|---|---|
| Prompt 内部自洽 | 通过：扩大召回、核心/观察分层和禁止绕过盘中风控无冲突 |
| Prompt 占位符与输出 | 通过：7 个输入占位符均由代码填充，JSON 字段均有解析与默认值 |
| Prompt 与代码契合 | 通过：数量上限、0.78 核心阈值、字段名和证据规则一致 |
| Python 语法与导入 | 通过：相关模块 `py_compile` 成功 |
| 代码内部一致 | 通过：主/影子状态和事件来源隔离，模拟与回测共用成交模型 |
| 投资逻辑合理 | 通过：扩大的是发现层，不是买入权限；原风控保护保持 |
| 核心目标对齐 | 通过：风控优先，其次封板/胜率、盈亏比、无效交易和合理频率 |

## 八、已知限制与下一步

- 当前事件回放验证的是“已记录决策在统一撮合下的表现”。实时决策部分仍有
  `datetime.now()` 依赖，若要让整个策略在历史 Tick 上重新决策，需要引入统一事件时钟；
  在完成前，不应把事件回放描述成完整的历史策略重演。
- 交易所真实排队位置不可从普通 Tick 精确恢复。当前模型有意偏保守，可能低估成交，
  但比高估涨停收益更适合作为晋级依据。
- Tick 数据量较大，应在空间充足的 SSD 保存，并对归档保留期、备份和校验失败告警
  建立运维规则。
- 事件日志目前足够重建排板所需的买一和累计成交证据；未来若研究五档扫板的精细
  反事实执行，应以完整 Tick 归档为准，或扩展事件快照。

推荐从下一个交易日开始持续采集 Tick，同时运行核心与扩展影子组；每日先校验归档，
每周只生成报告不改参数，累计满足样本门槛后再做一次冻结版本的正式 A/B 验收。
